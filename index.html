Built for Real Work

Production-grade control in a single container.

No external databases, message queues, or sprawling microservices to maintain. One lightweight Rust runtime bundles the web observatory, multi-agent orchestrator, SQLite storage, automatic HTTPS proxy, and browser engine.

01 · Zero-Config HTTPS & Auth

Ready for Local or LAN Deployment

Automatically generates a local Root CA and TLS server certificates at startup. Protected out of the box by Argon2id password hashing, strict session cookies, and fail-closed startup checks.

02 · Bring Your Own LLM Keys

OpenAI, Responses & Gemini Native

Connect OpenAI, Google Gemini, or any OpenAI-compatible endpoint (OpenRouter, Anthropic proxies, vLLM, Ollama) with configurable reasoning effort. Your API keys remain strictly on the server — never exposed to the browser.

03 · Reusable Skills & MCP Tools

Teach Playbooks & Connect Services

Give agents custom Markdown skills (SKILL.md) that you can trigger with / slash commands in chat, and connect external Model Context Protocol servers in mcp.json over stdio or Streamable HTTP — with every tool call recorded in an audit trail.

04 · Resilient Live Streaming

Never Lose an In-Flight Reply

Close your laptop, refresh the page, or switch networks mid-task. Every streamed token and agent status transition is committed atomically to SQLite so reconnecting browsers resume right where they left off.

05 · Scheduled Crew Routines

Put Recurring Work on Autopilot

Schedule daily briefings, repository audits, or smoke tests using cron expressions or intervals. Every run is governed by strict time and tool-call limits so background tasks never spiral into runaway API bills.

Attach up to 6 images per message (PNG, JPEG, WebP, GIF) to debug UI layouts or inspect diagrams. KrewOS automatically strips EXIF/location metadata and normalizes resolution before sending to your model.

Quickstart

Up and running with Docker Compose in two minutes.

Requires Docker (≥ 23.x) with Compose v2 and an OpenAI-compatible or Gemini API key.

Step 1

Clone the deployment kit & set your password and LLM key

The distribution repository includes compose.yaml, .env.example, mcp.json, and the container audit script:

git clone https://github.com/krewos/krewos.git
cd krewos
cp .env.example .env
docker run --rm -it ghcr.io/krewos/krewos:latest /usr/local/bin/krewos --hash-password

Paste the generated '$argon2id$...' hash (kept inside single quotes) into KREWOS_AUTH_PASSWORD_HASH in .env, then set KREWOS_LLM_BASE_URL and KREWOS_LLM_API_KEY.

Step 2

Start KrewOS & trust the auto-generated local HTTPS certificate

docker compose pull
docker compose up -d

compose.yaml publishes HTTP on port 80 (for certificate download and HTTPS redirect) and HTTPS on port 443. Install the generated Root CA from http://127.0.0.1/ca.crt so your browser opens https://krewos.localhost without TLS warnings: 

curl -fsSL http://127.0.0.1/ca.crt -o krewos-ca.crt && \
  sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain krewos-ca.crt && \
  rm krewos-ca.crt
sudo curl -fsSL http://127.0.0.1/ca.crt -o /usr/local/share/ca-certificates/krewos-ca.crt && \
  sudo update-ca-certificates
curl.exe -fsSL http://127.0.0.1/ca.crt -o krewos-ca.crt
certutil -addstore -f "ROOT" krewos-ca.crt
Remove-Item krewos-ca.crt

Then open https://krewos.localhost and sign in at /login (default username: owner).

Security & Zero-Trust Verification ("Verify the Cage")

Don't trust a closed binary — verify the kernel cage around it.

KrewOS is distributed as a compiled Rust binary inside a hardened single-container image (ghcr.io/krewos/krewos) under a Free Direct-Use / Zero-Monetization EULA. You never have to take our word for how it behaves: the entire container envelope is 100% plain-text (compose.yaml), enforced by the Linux kernel, and auditable in one command.

1 · Auditable Execution Envelope (compose.yaml)

Locked Down at the Linux Kernel Level

  • Read-Only Root Filesystem: Runs with read_only: true and security_opt: [no-new-privileges:true] so runtime binaries cannot be modified.
  • Dropped Kernel Capabilities: cap_drop: [ALL] — the supervisor process (0:0) only retains SETUID, SETGID, and KILL to place agents into unprivileged sandboxes (no CAP_DAC_OVERRIDE, no CAP_CHOWN, no CAP_NET_RAW).
  • Zero Host Exposure: No Docker socket (/var/run/docker.sock) mounted, no host ~/.ssh or ~/.aws mounts, default seccomp profile active, pids_limit: 2048 enforced, and only the unprivileged HTTPS proxy ports (80:8080, 443:8443) are published.
2 · Hardened Surface & Live Audit

Distroless Base (gcr.io/distroless/cc-debian13)

Built on top of gcr.io/distroless/cc-debian13, the runtime image strips out OS package managers (apt, dpkg), compilers (gcc, cc), privilege-escalation binaries (su, sudo, passwd, useradd, mount), and all SUID/SGID bits.

Verify all 35+ kernel, Distroless surface, and cross-agent isolation checks against your running container: 

bash scripts/container-security-check.sh

Multi-UID Discretionary Access Control (DAC)

Identity UID : GID Scope & Isolation Boundary
krewos 0:0 Rust supervisor bound to internal loopback (127.0.0.1:3000). Stripped of root file-override capabilities (CAP_DAC_OVERRIDE, CAP_CHOWN).
mcp 10001:10001 Isolated stdio MCP tool servers (uvx / bunx) confined to /var/cache/krewos-mcp (0700).
browser 10002:10002 Unprivileged Xtigervnc (:99, Unix socket only), Openbox, and @playwright/mcp (:8931, protected by internal auth token).
linuxbrew 10003:10003 Exclusive owner of /home/linuxbrew (0755), preventing PATH poisoning by agents; handles delegated brew installs over /tmp/.krewos-brew.sock.
nginx 10004:10004 Unprivileged TLS reverse proxy listening on container ports :8443 (HTTPS) and :8080 (HTTP redirect & /ca.crt).
agents 20001+ Dedicated monotonic UID/GID per agent (20001, 20002…). Confined to /workspace/<agent_id> (2770). An agent cannot read another agent's workspace, /var/lib/krewos, or the runtime environment.
